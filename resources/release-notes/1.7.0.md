# 1.7.0

silo 1.7.0 adds partial entry updates (`PATCH`), unauthenticated API and MCP
discovery endpoints at the server root, a major upgrade to entry editing, media
picking, collection search and per-server appearance in the admin, and builds
the executables and Docker image with Bun 1.4.5.

## New: partial entry updates (`PATCH`)

Update individual fields of an entry without sending the whole document or
accidentally resolving `{{NAME}}` variable templates.

- **RFC 7396 JSON Merge Patch over the stored raw entry.** Omitted fields keep
  their stored values, including untouched `{{NAME}}` templates and valid
  `silo://media/<id>` references. Nested plain objects merge recursively, arrays
  are replaced whole, and setting a field to `null` deletes it (failing schema
  validation with `400` if the field is `required`).
- **Revision-checked and validated like `PUT`.** `PATCH` requires `If-Match` or
  `?rev=` (`409` on mismatch), rejects non-object bodies and reserved envelope
  fields, runs plugin hooks and schema validation, and refuses an unrelated
  patch if the entry still holds a dangling `silo://media/<id>` reference until
  it is replaced or cleared with `null`.
- **Claims and content types.** Because the response returns untouched fields,
  `PATCH` requires an API key with both `entries:read` and `entries:update`.
  Send `Content-Type: application/merge-patch+json` or `application/json` (other
  or missing content types answer `400`). `?variables=raw` works on the response
  as on `GET`, `POST` and `PUT`.
- **Clients:** the TypeScript (`CollectionHandle.patch` and
  `EntryPatch<Fields>`), Dart and Java clients add `patch()` on collection
  handles, with automatic cache eviction.

**API:** `PATCH /api/projects/{project}/environments/{env}/collections/{name}/{id}`
(and the `/envs/` alias). The full guide is in
[http-api.md](https://github.com/org-quicko/silo/blob/v1.7.0/resources/guide/http-api.md#optimistic-concurrency--partial-updates).

## New: open discovery endpoints

AI agents and tools can inspect a running silo instance's API and MCP tools at
the server root before configuring an API key.

- **`GET /openapi.json`** serves the complete OpenAPI 3.1 HTTP specification
  (bundled into the compiled executable and Docker image).
- **`GET /mcp`** returns the MCP tool catalog (`name`, `title`, `description`,
  `inputSchema` and `annotations`), transport details, auth requirements and
  server instructions. `POST /mcp` answers `405` pointing to `POST /api/mcp`,
  which remains API-key-gated.
- **`GET /llms.txt`** returns a plain-text Markdown guide explaining how to use
  `/openapi.json`, `/mcp`, `POST /api/mcp`, API keys and claims, queries,
  optimistic concurrency, variables, media and trash.

All three endpoints accept `GET` and `HEAD` without authentication, enable
cross-origin `GET`/`HEAD` requests, set `X-Content-Type-Options: nosniff` and
`Cache-Control: no-cache`, and answer `405 method_not_allowed`
(`Allow: GET, HEAD`) to mutating methods. The MCP guide is in
[mcp.mdx](https://github.com/org-quicko/silo/blob/v1.7.0/docs/guides/mcp.mdx#open-discovery).

## New: entry and schema editing in the admin

- **Form and JSON modes for entries.** The entry editor adds a **Form | JSON**
  toggle so you can edit an entry as a generated form or as raw JSON.
- **Strict client-side JSON Schema validation in JSON mode.** Entry JSON is
  validated against the collection's schema (Draft 2020-12 and Draft-07) as you
  type. Undeclared keys, reserved envelope fields, type or constraint
  violations and unsafe numbers are underlined inline with hover tooltips and a
  clickable error list, and block Save. `any` (`{}`) and free-form
  `{ "type": "object" }` fields remain open. Switching from **JSON** back to
  **Form** is blocked when unknown keys or widget-incompatible values would be
  dropped.
- **Dual-mode Visual Tree and CodeMirror JSON editor.** `any` and fallback JSON
  fields move from a plain textarea to a **Visual | Code** editor:
  - **Visual** (default for values up to 200 nodes) edits objects, arrays and
    scalars in a collapsible tree with inline key renaming, type switching,
    array reordering and duplication.
  - **Code** uses CodeMirror with syntax highlighting, bracket matching, code
    folding, `⌘F`/`Ctrl+F` search, inline error diagnostics, a toolbar
    (**Format**, **Compact**, **Sort keys**, **Wrap**, **Copy**, **Expand**)
    and a full-width expand modal. Entry JSON mode shares the same toolbar and
    modal; the schema editor's **Code** tab adds **Format**, **Wrap**, **Copy**,
    **Expand** and a footer **Jump to error** action.
- **Unsaved-change guards, `⌘S`/`Ctrl+S` and stale-revision detection.** Entry
  and schema editors prompt before discarding unsaved changes across in-app
  navigation, browser Back/Forward, tab close/reload, **Discard** and `Esc`,
  and bind `⌘S`/`Ctrl+S` to save. Once an entry has unsaved edits, its starting
  revision stays locked so background refreshes never clobber your draft; if a
  newer revision appears on the server, a warning banner offers **Reload**, and
  a `409` conflict preserves your draft.

## New: collection search, saved table layout and full media picker

- **Inline collection search.** The entries toolbar adds a debounced search box
  (`?q=`) over the collection's search index (`Enter` searches at once; `Esc`
  clears or blurs).
- **Remembered columns and page size.** Chosen extra columns and page size
  (`10`/`25`/`50`/`100`) are saved per server, scope and collection in browser
  storage, while an explicit `?cols=` in the URL still overrides the saved
  layout so shared links stay intact.
- **Return where you left off.** Saving, discarding, deleting, clicking
  breadcrumbs or using Back/Forward returns to the exact entries list URL
  (search, filter, sort, page and columns) and restores the keyboard row cursor.
  Deleting the last items on a trailing page steps back to the last valid page.
- **Full-library Media Picker and drop/paste upload.** **Select Media File** on
  media fields now paginates (`24`/`48`/`96`) across the entire library instead
  of capping at 100 items, with folder filtering, MIME type filters
  (**Images**, **Video**, **Audio**, **PDF**, **Text**), search and
  folder-targeted uploads. Media fields also accept single-file drag-and-drop
  and clipboard file paste when the key holds `media:create`; failed uploads
  keep the existing value intact behind a dismissible error banner, and Save or
  switching to JSON mode waits until an upload finishes.

## New: per-server appearance settings

Theme mode (dark or light), preset, custom accent hex and typeface are now
stored per saved server in browser storage, so you can give production, staging
and local instances distinct looks.

- **In the admin:** open **Settings > Server > Appearance** (the light/dark
  toggle in the Settings header and sidebar also applies only to the active
  server).
- **Migration:** existing global appearance settings are copied once to your
  already-saved servers; new connections start on Silo defaults, and forgetting
  a server removes its saved appearance.

## Changed: built with Bun 1.4.5

- The release executables and the Docker image (`oven/bun:1.4.5-alpine`) now
  use Bun 1.4.5 instead of 1.4.4.

## Fixes

- **Entries with a field named `data` or `collection` are no longer corrupted in
  the admin.** The entry decoder previously unwrapped a nested `data` property
  and stripped `collection` heuristically, breaking schemas that declared those
  field names.
- **Switching API keys no longer logs out the active session on late `401`
  responses.** In-flight requests from a previous key (and pending trash-undo
  restores) are scoped to the session that started them.
- **Schema save, rename and delete no longer race in the admin.** Saving,
  renaming and deleting a collection are mutually exclusive, renaming is blocked
  while schema edits are unsaved, and refreshes during a mutation no longer
  trigger false missing-collection redirects.
- **MCP media tool descriptions drop a stale claim note.** `list_media` and
  `get_media` no longer state `Needs media:read.`, which was retired in an
  earlier release.
