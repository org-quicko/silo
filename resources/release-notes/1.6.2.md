# 1.6.2

silo 1.6.2 lets you change the schema of a collection that already has entries,
as long as every existing entry still fits the new schema. The admin also shows
a saved schema straight away, without a reload.

## Changed: schema changes on a collection with entries

Before 1.6.2, any change to the validating shape of a collection was refused
while the collection held an entry. Now silo checks the change against every
entry first.

- **A change that every entry satisfies is saved.** Adding an optional field,
  loosening a constraint and similar changes now go through on a populated
  collection.
- **A change that an entry breaks is refused.** The save answers `409` and
  saves nothing. The message names the collection only: the check stops at the
  first entry that fails, so it does not list every one.
- **Titles, descriptions and search settings never block a save.** A change to
  `title`, `description`, `$comment`, `$schema` or `x-silo-search` is never
  refused this way. `x-silo-auth` still needs `collections:…:access:update`, as
  before.
- **The admin schema editor is editable on a populated collection.** The
  read-only banner is gone, and `x-silo-search` can be changed again.
- **Imports and transfers are unchanged.** They still refuse any change of
  shape over existing entries.

**API:** `PUT …/schema` can now answer `409` for a schema that existing entries
do not satisfy. The MCP `update_schema` tool's description states the new rule.

## Fixed: a saved schema shows in the admin without a reload

After saving a schema, the editor, the entries table columns and the entry form
kept the old schema until a full page reload. They now update as soon as the
save completes.

## Version

- Package versions are 1.6.2 in the root, `apps/admin`, `apps/server`,
  `packages/create-silo-plugin` and `packages/shared`.
