# 1.6.1

silo 1.6.1 fixes the folder counts in the Media Library on SQLite storage.

## Fixes

- **A folder with many subfolders shows the right count for each one**
  ([#59](https://github.com/org-quicko/silo/issues/59)). The Media Library
  asks the server for one count per subfolder. On SQLite, a folder with more
  than about 30 subfolders sent more requests than the server could queue at
  the same time. The server refused some of them with `503 busy`, and the admin
  showed too few items for those folders. Before 1.5.0, the server answered
  these requests with `401 invalid API key`, even for a valid key.
  - **Server:** a list on SQLite now reads the page and its total in one query,
    as on Postgres. Each request takes one place in the read queue instead of
    two, so 64 requests can wait at the same time instead of 32.
  - **Admin:** the Media Library asks for at most 6 folder counts at a time,
    and each request asks for one item instead of a page of 50.
